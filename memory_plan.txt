TUNDA 1 — RELOKASI FOLDER TANPA RE-ENCODE (PRIORITAS USER)
================================================================================
Masalah:
  Struktur RAW berubah, mis. dulu 'anime/tskb/' (datar) kini jadi
  'anime/tskb/1/' dan 'anime/tskb/2/'. Karena judul kini menyebut >1 folder
  tujuan, ancestor_fallback_allowed() = False -> folder 'anime/tskb/1' tidak
  ditemukan -> S1 dianggap belum diproses -> DI-ENCODE ULANG (buang waktu ~jam).

Yang diinginkan:
  Deteksi bahwa folder lama sudah berisi episode musim yang bersangkutan, lalu
  PINDAHKAN (git mv via Git Data API) ke struktur baru TANPA encode ulang.

Rancangan:
  - Skrip/mode baru, mis. 'relocate_drive_folders.py' atau
    'process_release_archive.py --relocate'.
  - Input: peta 'folder_lama -> folder_baru' (mis. anime/tskb -> anime/tskb/1).
  - Teknik: Git Data API (sama seperti penghapusan folder HLS rusak):
      1. Baca tree subtree lama (main:<folder_lama>?recursive=1).
      2. Buat tree baru dengan semua blob di-prefix folder_baru.
      3. Commit sekali, hapus path lama.
  - Aman: idempotent, dry-run dulu, jangan mengubah isi file (blob tetap sama).
  - Setelah relokasi, jalankan --sync-metadata agar metadata.json ikut terbarui.
  - Verifikasi: masukkan ke proses plan (--check-skip) supaya S1 jadi skip=true.

TUNDA 2 — ANTRIAN JOB TANPA BATAS (WAIT-LIST)
================================================================================
Kondisi sekarang:
  process-release-hls.yml sudah punya:
      concurrency:
        group: "hls-release-processing"
        cancel-in-progress: false
  Efeknya: job yang berjalan TIDAK dibatalkan, tapi GitHub hanya menyimpan
  SATU run "pending" per grup. Trigger ke-3 akan membuang pending sebelumnya.

Yang diinginkan:
  Antrian tanpa batas (atau batas tinggi) dan tidak saling membatalkan.

Rancangan (file daftar tunggu):
  - Simpan antrian di sebuah file/issue/label (mis. 'pending_queue.json' di repo
    atau label 'queue:menunggu' pada issue).
  - Workflow job "queue" menerima release_tag dan memasukkannya ke daftar tunggu.
  - Job "runner": selama daftar tunggu tidak kosong, ambil item teratas, proses,
    tandai selesai, ulangi. Selalu hanya satu runner yang berjalan.
  - Jika ada job baru saat runner berjalan, hanya ditambahkan ke daftar (tidak
    memicu run baru), sehingga tidak ada pending yang terbuang.
  - Alternatif: self-hosted runner + satu worker loop.

TUNDA 5 — PWA (INSTALLABLE + OFFLINE + CACHE VIDEO + LAYAR PENGATURAN)
================================================================================
Permintaan user:
  - PWA bisa diinstal.
  - Bisa offline.
  - Video yang PERNAH DITONTON otomatis ter-cache.
    CATATAN PENTING: aplikasi saat ini TIDAK punya opsi unduh sama sekali.
    Jadi cache offline murni berasal dari video yang DITONTON. Tombol
    unduh/simpan-offline adalah fitur BARU (belum ada) — lihat (Opsional) di bawah.
  - Layar pengaturan: tampilkan info UKURAN CACHE + tombol BERSIHKAN cache.

Prasyarat:
  - Situs harus via HTTPS (sudah: https://stream.rasyidkurniawan.my.id/).
  - Scope di root '/', start_url '/'. OK karena domain custom (bukan subfolder).

Komponen yang perlu dibuat:
  1) manifest.webmanifest
       { name, short_name, start_url: "/", scope: "/", display: "standalone",
         background_color, theme_color, icons: [192, 512, maskable] }
     Index.html: <link rel="manifest" href="manifest.webmanifest">
     Catatan: perlu IKON PNG 192 & 512 (favicon.ico bisa dijadikan sumber,
     tapi sebaiknya PNG asli). Taruh di assets/icons/.
     -> User minta AI yang MEN-GENERATE ikon ini nanti (bukan user).
  2) sw.js (Service Worker) — didaftarkan dari JS (mis. assets/js/pwa.js):
       - Versi cache: CACHE_VERSION = "v1" agar bisa invalidasi.
       - APP SHELL (precache saat install): "/", "index.html",
         "assets/css/*.css", "assets/js/*.js", "favicon.ico", manifest.
       - Strategi runtime:
           * metadata.json & aliases.json : network-first + fallback cache
             (stale-while-revalidate) -> UI tetap jalan offline.
           * HLS playlist (.m3u8)         : network-first, fallback cache.
           * Segmen video (.ts)           : CACHE-FIRST -> inilah yang membuat
             "video yang pernah ditonton" otomatis tersimpan saat diputar.
           * Poster (.jpg/.png) & .vtt    : cache-first.
       - Penting: batasi pertumbuhan. Simpan metadata waktu akses, lalu evict
         (LRU) bila melewati batas (mis. 2 GB atau N entri) — Cache Storage
         tidak punya auto-evict saat offline-nya sendiri.
       - activate: hapus cache versi lama; clients.claim().
       - message handler untuk layar pengaturan:
           {type:"CACHE_SIZE"} -> balas daftar cache + jumlah entri + ukuran.
           {type:"CLEAR_CACHE"} -> hapus semua cache media (sisakan app shell).
  3) Layar PENGATURAN (modal di index.html + assets/js/settings.js):
       - Ukuran cache: pakai navigator.storage.estimate() (usage/quota) +
         caches.keys() + caches.open().keys() untuk rincian per-cache.
       - Tombol "Bersihkan Cache": kirim CLEAR_CACHE ke SW, lalu refresh angka.
       - (Opsional, FITUR BARU — belum ada) tombol "Simpan offline episode ini"
         untuk mengunduh SEMUA segmen satu episode sekaligus (bukan hanya yang
         terlewat saat nonton).
       - (Opsional) navigator.storage.persist() untuk minta penyimpanan
         persisten agar cache tidak dibersihkan browser.

Jebakan yang harus diingat:
  - Cache-first untuk .ts berarti update konten tidak terlihat sampai versi
    cache dinaikkan -> naikkan CACHE_VERSION saat ada perubahan media.
  - Offline hanya berisi episode yang sudah pernah DITONTON (dan/atau yang
    diunduh lewat tombol simpan-offline, bila fitur itu dibuat nanti); bukan
    seluruh library (terlalu besar).
  - Jangan cache respons lintas-origin secara membabi-buta; hanya URL CDN
    stream_drive + app shell sendiri.
  - GitHub Pages: SW di root, pastikan header tidak memblokir (Pages tidak
    mengirim header yang menghalangi SW).

Rencana berkas:
  + manifest.webmanifest, sw.js, assets/js/pwa.js, assets/js/settings.js,
    assets/icons/icon-192.png, assets/icons/icon-512.png
  ~ index.html (link manifest, tombol pengaturan, registrasi SW)

PANDUAN SETUP API RESMI MyAnimeList
================================================================================
Tujuan: dapat 'client_id' untuk membaca data anime (judul + gambar) secara legal.

Langkah:
  1. Login ke https://myanimelist.net/ dengan akun MAL.
  2. Buka https://myanimelist.net/apiconfig
     (menu: Preferences -> API, atau langsung URL itu).
  3. Klik "Create ID".
  4. Isi form:
       - App Name           : <nama bebas, mis. "Stream Hub Metadata">
       - App Type           : Web
       - App Description    : <deskripsi singkat>
       - App Redirect URI   : <boleh http://localhost:8000/callback untuk uji lokal>
  5. Setelah dibuat, MAL menampilkan:
       - Client ID   <-- INI yang kita butuh
       - Client Secret
  6. Simpan sebagai environment variable (JANGAN di-commit):
       export MAL_CLIENT_ID="xxxxxxxxxxxxxxxxxxxxxxxx"
  7. Uji cepat (anime Fruits Basket sebagai contoh):
       curl -s "https://api.myanimelist.net/v2/anime?q=fruits%20basket&limit=3" \
            -H "X-MAL-CLIENT-ID: $MAL_CLIENT_ID" | python3 -m json.tool | head -40

Endpoint yang akan dipakai:
  - Pencarian    : GET /v2/anime?q=<judul>&limit=5
  - Detail       : GET /v2/anime/<id>?fields=id,title,main_picture,alternative_titles,start_date
  - Gambar sampul: field 'main_picture' (large/medium)

PENTING soal legalitas:
  - Gunakan HANYA API resmi di atas. Scraping halaman web MAL melanggar ToS.
  - Sumber tidak resmi (mis. Jikan) tidak dipakai karena bukan sumber resmi.
  - Hormati rate limit API MAL (jangan spam; beri jeda antar request).

CARA SET ENVIRONMENT VARIABLE DI GITHUB REPO
================================================================================
Untuk nilai yang dipakai workflow (mis. MAL_CLIENT_ID):

NON-RAHASIA (repository variable):
  1. Buka repo -> Settings -> Secrets and variables -> Actions.
  2. Tab "Variables" -> "New repository variable".
  3. Name  : MAL_CLIENT_ID
     Value : <nilai>
  4. Simpan. Dipakai di workflow: ${{ vars.MAL_CLIENT_ID }}

RAHASIA (repository secret):
  1. Sama seperti di atas, tapi tab "Secrets" -> "New repository secret".
  2. Name  : MAL_CLIENT_ID
     Value : <nilai>
  3. Dipakai di workflow: ${{ secrets.MAL_CLIENT_ID }}

Catatan:
  - Secret tidak bisa dibaca ulang setelah disimpan (write-only).
  - JANGAN pernah menaruh token/API key di file yang di-commit.
  - Bisa juga lewat CLI:
      gh variable set MAL_CLIENT_ID --repo krasyid822/stream --body "..."
      gh secret   set MAL_CLIENT_ID --repo krasyid822/stream

================================================================================
TIPS AGAR TIDAK BOROS KUOTA API MYANIMELIST
================================================================================
  - Ambil hanya field yang perlu: pakai parameter 'fields='
    (mis. fields=id,title,main_picture,synopsis).
  - Cache hasil ke metadata proyek sendiri: simpan judul + sampul hasil MAL
    LANGSUNG ke metadata.json / aliases.json (sesuai catatan user), sehingga
    tidak perlu memanggil API dua kali. Sertakan timestamp sumbernya.
    (Boleh juga mal_cache.json sebagai perantara, lalu ditulis ke aliases.json.)
  - Cari sekali per judul unik, lalu simpan id MAL-nya; setelah itu detail
    via id (bukan pencarian berulang).
  - Beri jeda kecil antar request (mis. 0.5-1 detik) dan tangani 429 dengan
    backoff eksponensial.
  - Saat pengembangan, cukup 1-2 judul untuk uji; jangan menarik seluruh library.
